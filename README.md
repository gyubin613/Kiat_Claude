# 평가위원 섭외 및 일정조율 통합관리 웹시스템 (시제품)

평가위원 명단 관리 → 섭외 우선순위 검토 → 초청 메일 → 평가위원 웹 회신 → 회신 취합 → 최종 확정까지를 **하나의 웹 화면**에서 처리하는 업무지원 시제품입니다.

> ⚠️ 본 시제품은 **가상 데이터** 기반의 시연·검증용입니다. 실제 평가위원 개인정보나 기관 내부 업무자료를 입력하지 마십시오. 기관 내 실제 적용 및 외부 서비스 연계는 관계부서의 사전 검토·승인 후 별도로 결정합니다.

---

## 1. 주요 기능 (계획서 4장 대응)

| 계획서 | 화면 | 구현 내용 |
|---|---|---|
| 가. 평가 일정·기본정보 | ① 평가 일정 등록 | 복수 평가 독립 관리, 후보 일정·장소 복수 등록(+1일 복사), 현재 평가 상단 고정, 새로고침·메뉴 이동 후에도 선택 유지 |
| 나. 명단 등록·수정 | ② 평가위원 명단 | 엑셀 일괄 등록(미리보기 → 중복 처리 방식 선택 → 결과), 누락 항목 등록 후 보완, 이메일·성명+소속 중복 확인, **한 화면 수정창에서 바뀐 항목만 저장**, 엑셀 내보내기·등록 양식 |
| 다. 우선순위·순차 섭외 | ③ 섭외 우선순위 | 이력 점수(라플라스 보정) + 관리자 선호도, 가중치 슬라이더, 이력 없음은 중립값, 배석 인원 자동 선정, 불참·철회 시 후순위(2차·3차) 추가 섭외. 점수는 **참고자료**임을 명시 |
| 라. 초청 이메일 | ④ 초청 메일 | 평가별 메일 양식(자동 입력 항목), 위원별 고유 회신 링크, 미리보기, 업무용 메일 앱 열기·복사(수동 발송 우선), 발송 이력·상태, Resend 시험 발송(수신자 허용목록 제한) |
| 마. 평가위원 회신 | `/r/{링크}` | 설치·로그인 없이 응답, 참석 가능/조건부/불가, 복수 일정 선택, 불참 시 일정 단계 생략, 확정 전 응답 수정, 모바일 최적화 |
| 바. 회신 취합 | ⑤ 회신 현황 · 캘린더 | 회신/미회신 구분, 일정별 가능 인원 자동 집계(조건부 구분), 이름·소속 검색, 15초 자동 갱신, 월별 캘린더, 엑셀 다운로드(회신 현황·일정별 집계·확정 결과) |
| (추가) 위원 소통 | 위원 문의·안내 | 위원이 회신 전에도 회신 화면에서 문의 → 관리자 문의함(미확인 배지) → 답변 게시 + 메일 발송, 전체·대상별(전체/회신 대기/참석 가능) 안내사항 게시 + 메일 발송. 메일 서비스 미설정 시 '메일 앱으로 열기'로 수동 발송 |
| (추가) 자동 후속 안내 | ① 평가 수정 · ④ 초청 메일 | 평가별로 기간(24·48·72시간 또는 직접 입력) 설정. 발송 후 기간 내 무응답(선택: 참석 불가 회신)이면 부족 인원만큼 우선순위 다음 위원을 자동 초청·메일 발송. 남은 시간 표시, '지금 점검' |
| (추가) 조건부 참석 문의 | 회신 현황 · 위원 문의·안내 | 조건부 회신에는 조건·문의사항 필수 → 문의함에 자동 등록. 관리자가 그 자리에서 답변하며 수락·거절(또는 답변만). 수락한 위원만 확정 가능(서버 검증), 거절은 불참으로 집계. 위원이 회신을 고치면 다시 검토 |
| (추가) 확인 요청 | 위원 문의·안내 | 관리자가 위원별 '확인 요청'을 보내거나 안내사항에 '답변 요청' → 위원 회신 화면 맨 위에 답변란 → 관리자 화면에 답변 대기/답변 받음 표시 |
| (추가) 평가별 위원 명단 | 평가 등록 · 평가위원 명단 | 평가마다 명단을 따로 관리. 새 평가 등록 시 '새로 올리기' 또는 '이전 평가에서 불러오기(일괄/선택)'. 불러온 위원은 평가별 복사본이라 수정해도 원래 평가에 영향 없음. 이전 평가 결과(초청·참여)를 과거 이력에 반영 선택. 명단 엑셀 다운로드 → 편집 → 다른 평가에 업로드, 엑셀로 추가·업데이트 |
| (추가) 자동 섭외 | 평가 등록 · 우선순위·섭외 | 평가 등록 시 '자동 섭외' 선택 → 위원 순서를 끌어서(또는 ↑↓) 정하고 제외 지정 → [자동 섭외 시작] 시 배석 인원만큼 앞 순서부터 즉시 메일 발송. 불참·조건부 거절·철회는 즉시, 무응답은 정한 시간 후 다음 순서로 자동 발송. 중지 가능 |
| (추가) 학력·해외경험 | 평가위원 명단 · 우선순위 | 학사·최종학력(학교·전공·국내/해외), 해외 근무 경력. 가중치 3요소(과거 이력·선호도·해외경험). 평가별 '이해관계 확인 기관'과 소속·학교가 겹치면 표시 |
| 사. 최종 확정 | ⑥ 최종 확정 | 일정별 인원 비교, 최종 일시·참석자 선정, **확정 후 변경 차단**(평가·초청·회신 모두), 확정 시점 성명·소속 스냅샷 보존 → 기본정보 정정과 결과 분리 |

계획서 8장 시험 항목과 자동 테스트의 대응은 [`docs/traceability.md`](docs/traceability.md) 참고.

## 2. 빠르게 실행해 보기 (로컬)

```bash
npm install
npm run dev
# http://localhost:3000  → 비밀번호 demo1234 (개발 모드 기본값)
# 첫 화면에서 [가상 데이터 불러오기] → 평가 3건, 평가위원 30명이 생성됩니다
```

로컬에서는 Redis 없이 서버 메모리에 저장됩니다(재시작 시 초기화).

## 3. Vercel 배포

1. 이 저장소를 Vercel에 Import (Framework: Next.js 자동 인식)
2. **Storage → Marketplace → Upstash for Redis** 를 프로젝트에 연결 → `KV_REST_API_URL`, `KV_REST_API_TOKEN` 자동 설정
3. **Settings → Environment Variables** 에 추가
   | 변수 | 필수 | 설명 |
   |---|---|---|
   | `ADMIN_PASSWORD` | ✅ | 관리자 비밀번호 (미설정 시 배포 환경 로그인 불가) |
   | `SESSION_SECRET` | 권장 | 세션 서명 키 (`openssl rand -hex 32`) |
   | `NEXT_PUBLIC_GITHUB_REPO` | 권장 | `owner/repo` — 앱 안 피드백 버튼 연결 |
   | `KV_PREFIX` | 선택 | Preview·Production이 같은 Redis를 쓸 때 구분 (예: `kiat-preview:`) |
   | `RESEND_API_KEY`, `EMAIL_FROM`, `EMAIL_ALLOWED_RECIPIENTS` | 선택 | 이메일 발송 (초청·답변·안내·자동 후속). 허용목록 밖 주소는 발송하지 않음 |
   | `ADMIN_NOTIFY_EMAIL` | 선택 | 위원 문의 접수·자동 후속 처리 결과 알림 받을 주소 |
   | `CRON_SECRET` | 자동 후속 사용 시 | 스케줄러 호출 인증 키 (`openssl rand -hex 32`) |
4. Deploy → 이후 `main`에 push하면 자동 배포, PR마다 미리보기(Preview) 주소 생성

> Redis 없이 Vercel에 배포하면 서버 인스턴스마다 데이터가 따로 저장되어 화면이 어긋날 수 있습니다. 상단에 "시연 모드" 경고가 보이면 Redis를 연결하세요.

### 메일 실제 발송

관리자 화면 왼쪽 **메일 설정** 메뉴에서 현재 상태 확인과 시험 발송을 할 수 있습니다.

| 변수 | 예 | 설명 |
|---|---|---|
| `SMTP_HOST` | `smtp.naver.com` | 메일 계정의 보내는 메일 서버 (Gmail `smtp.gmail.com`) |
| `SMTP_PORT` | `465` | 465(SSL) 또는 587(STARTTLS) |
| `SMTP_USER` | `id@naver.com` | 전체 메일 주소 |
| `SMTP_PASS` | (앱 비밀번호) | 네이버: 2단계 인증 → 애플리케이션 비밀번호. 메일 환경설정에서 IMAP/SMTP 사용 켜기 |
| `EMAIL_FROM_NAME` | `기술평가팀` | 받는 사람에게 보이는 이름 |
| `EMAIL_ALLOWED_RECIPIENTS` | `me@naver.com,@example.org` | 위원에게 보낼 수 있는 주소. `*`는 모두 허용 (기관 승인 후) |
| `ADMIN_NOTIFY_EMAIL` | | 문의 알림 + 답장 받을 주소 |

Resend를 쓸 경우 `RESEND_API_KEY`, `EMAIL_FROM` (발신 도메인 인증 필요). SMTP가 설정되어 있으면 SMTP가 우선입니다.

### 무응답 자동 후속 안내 스케줄러

| 방식 | 주기 | 설정 |
|---|---|---|
| Vercel Cron (`vercel.json`) | 하루 1회 (09시 KST 무렵) | `CRON_SECRET` 환경변수만 있으면 자동. Hobby 요금제는 하루 1회까지만 허용 |
| GitHub Actions (`.github/workflows/followup.yml`) | 매시간 | 저장소 Settings → Secrets → Actions에 `APP_URL`(배포 주소), `CRON_SECRET` 등록 |
| 관리자 화면 | 화면을 열 때(10분 간격) · '지금 점검' 버튼 | 설정 불필요 |

> 메일 자동 발송은 `RESEND_API_KEY`·`EMAIL_FROM`과 수신자 허용목록(`EMAIL_ALLOWED_RECIPIENTS`)이 있어야 동작합니다. 없으면 다음 순위 위원을 초청 대상에 추가하고 ④ 화면에 '발송 필요'로 표시합니다. 실제 위원 대상 자동 발송은 발신 도메인 인증·기관 보안정책 검토 후 결정하십시오.

## 6. 보안·운영 메모 (계획서 6장 나.)

- 관리자 화면·API는 서명된 HttpOnly 쿠키 세션으로 보호, 평가위원 화면은 별도 경로로 분리
- 회신 링크는 192bit 난수 토큰. 단, **링크 소지가 본인 인증을 보장하지 않으므로** 실운영 시 본인확인(예: 휴대폰 인증번호) 추가 검토 필요
- API 키·비밀번호는 코드에 포함하지 않고 환경변수로 관리
- 동시 수정: 모든 문서에 버전을 두고 Redis Lua 스크립트로 비교 후 저장(CAS) → 충돌 시 최신 값을 보여주고 재저장 유도
- 이메일 직접 발송은 허용목록 주소로만 가능 (기본값: 직접 발송 불가)
- 실운영 전 검토 필요: 개인정보 처리 범위·보관기간·삭제, 접근기록, 백업, 로그인 시도 제한, 기관 보안정책

## 7. 함께 들어 있는 앱: 과제 서류 메일 정리 도우미
`mail-collector/` 폴더는 별도 앱입니다. K-PASS 밖(메일)으로 들어오는 과제 제출 서류를 과제 목록에 맞춰 분류하고,
제출현황 엑셀과 과제별 폴더로 정리합니다. 사용법·배포는 [mail-collector/README.md](mail-collector/README.md)를 보세요.
Vercel에서는 같은 저장소로 프로젝트를 하나 더 만들고 **Root Directory를 `mail-collector`** 로 지정합니다.
